## 3. The project

A **Study Assistant** (not a true agent, by design) for the course lectures:

1. **Explain** — ask about a topic → hybrid search over lecture slides → LLM explains **only from the slides** and cites them like `[K-means p.12]`.
2. **Quiz me on this** — button under the explanation → generate MCQs **from the same retrieved slides**, in the style of the Huawei HCIA exam (few-shot from the question bank).
3. **Practice from bank** (if time) — show a real bank question; our RAG answers it from the lectures and shows the source slide.

**Why not an agent?** The flow is known in advance, so there is no need for the LLM to decide the steps. A fixed flow is cheaper, faster and predictable in a live demo. Real tool-calling agent and intent detection = future work.

### 6.2 Chunking: page-based (one slide = one chunk)
- First experiment was **agentic chunking** (LLM decides YES/NO per paragraph) on `Fine_Tuning_LLMs.pdf` → 26 chunks. Kept in the notebook **Appendix** for the presentation comparison.
- Replaced because: it joins pages before splitting → **loses page numbers**; one API call per paragraph → too slow/costly for 22 PDFs; slides already hold ~one idea each.
- Per page: `fix_spaced_letters` cleaning (`Q U A N T I Z E D` → `QUANTIZED`) → skip if `< MIN_CHARS (30)` → skip if exact text already seen → keep.

### 6.3 Index details
- Chunk id: `f"{lecture}_p{page}"` (e.g. `KNN_p14`) — unique across files and readable as a citation.
- Metadata: `{"lecture": str, "page": int, "source": filename}`.
- Lecture name from filename via `clean_lecture_name()` (removes `_Nancy Ahmed`, `(2)`, underscores).
- **Embedded text = `"[{lecture}]\n{text}"`** — many slides never mention their topic, so prefixing the lecture name helps both dense and TF-IDF retrieval.
- Collection name: `"lectures"`.
- Filter one lecture: `collection.get(where={"lecture": "KNN"})`.

### 6.4 Retrieval & generation
- `hybrid_search(query, alpha=0.5, top_k=3)`: dense cosine from Chroma + TF-IDF dot product, each min-max normalized, combined as `alpha * dense + (1 - alpha) * sparse`. Returns dicts with `id, lecture, page, text, score`.
- `alpha=0.5` is currently **not justified by data** → evaluation task below.
- `rag_answer(query)` returns `(answer, retrieved_chunks)`. The retrieved chunks = "the part the student asked about" → reused by the quiz.
- Prompt: answer only from context, partial coverage allowed with a note, `"I don't know based on the lectures."` only if nothing related, cite `[Lecture p.X]`.

### 6.5 Question bank (`question_bank.json`)
- 130 questions, 10 sections, **100 single / 30 multiple** ("select all that apply"), all have 4 options A–D.
- Schema: `{"id": "bank_2", "section": "...", "type": "single"|"multiple", "question": "...", "options": {"A": "...", ...}}`
- **No answers in the bank.**
- The bank is HCIA-based, the lectures are from the NTI course → some sections (e.g. **Parallel Training**) are likely **not covered** by the lectures.
- ⇒ **New quiz questions are generated ONLY from lecture slides. The bank is used ONLY for style (few-shot).** Never generate questions from the bank content.

## 8. Next steps (in order)

### Step A — Quiz generation (notebook first, then app)
- Input: the `retrieved_chunks` from `rag_answer` (or random slides of one lecture via metadata filter).
- Few-shot style: embed bank questions with the same `dense_model`, pick the **3 closest** bank questions to the topic, put them in the prompt as **style examples only**.
- Ask the LLM for **JSON only**, e.g.:
  ```json
  {"questions": [
    {"type": "single", "question": "...", "options": {"A": "...", "B": "...", "C": "...", "D": "..."},
     "answer": ["B"], "explanation": "...", "source": "K-means_p12"}
  ]}
  ```
  - `answer` is always a list (1 item for single, 2+ for multiple).
  - `source` must be one of the given chunk ids.
- Validate in Python: parse with `json.loads` (handle failure gracefully), check 4 options, answer letters exist in options, source is in the given ids. Drop invalid questions instead of crashing.
- Grading: single → chosen letter == answer; multiple → `set(chosen) == set(answer)` (all-or-nothing, like the Huawei exam).
- Explain to me why JSON (code needs the correct answer to grade) and why grounding (no questions from outside the syllabus).

### Step B — Update `app.py`
- Load once with `@st.cache_resource`: dense model, Chroma collection, TF-IDF fit on stored docs, bank JSON.
- Chat/explain box → shows answer + expandable sources (lecture + page + slide text).
- Save `retrieved_chunks` in `st.session_state` → **"📝 Quiz me on this"** button → quiz with radio (single) / checkboxes (multiple) → submit → score + explanation + "review this slide" for wrong answers.
- Explain `st.session_state` to me (Streamlit re-runs the whole script on every click).
- Keep the UI simple and demo-safe.

### Step C — Evaluation (important for the 20-point criterion)
- Build ~15–20 test questions by hand with the **correct chunk id(s)**.
- Metric **Hit@3**: was a correct chunk in the top 3?
- Compare `alpha = 0` (TF-IDF only), `0.5` (hybrid), `1` (dense only) → table + simple bar chart for slides.
- Explain the result honestly, even if hybrid is not the best.
